## 设计模式
<details class="lake-collapse"><summary id="ue9350891"><span class="ne-text">设计模式是什么，有哪些类</span></summary><p id="uc8b2105b" class="ne-p"><span class="ne-text">设计模式是软件工程中常用的解决特定问题的模版或者蓝图，可以帮助我们开发者以一种更加清晰、高效和可重用的方式来编写代码。通常分为三类：</span></p><ol class="ne-ol"><li id="u17e8945e" data-lake-index-type="0"><span class="ne-text">创建型模式</span><span class="ne-text">：涉及对象实例化，用于创建对象的模式，可以增加程序的灵活性和可重用性。常见的创建型模式有工厂方法、抽象工厂、单例、建造者、原型等。</span></li><li id="ucec286ab" data-lake-index-type="0"><span class="ne-text">结构型模式</span><span class="ne-text">：涉及类和对象的组合，用于设计类和对象的结构，以便更好地实现程序的功能。常见的结构型模式有适配器、桥接、组合、装饰、外观、享元、代理等。</span></li><li id="u3dfee71f" data-lake-index-type="0"><span class="ne-text">行为型模式：关注对象之间的通信，包括责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者等。</span></li></ol></details>
## 创建型模式
### **单例模式**
<details class="lake-collapse"><summary id="u911cff1b"><span class="ne-text">是什么？应用场景？优缺点？</span></summary><ol class="ne-ol"><li id="u8c7d81e2" data-lake-index-type="0"><span class="ne-text">是什么<br /></span><span class="ne-text">单例模式是一种 创建型设计模式，它保证一个类在整个应用中 只有一个实例，并提供一个 全局访问点 来获取该实例。</span></li><li id="u98349261" data-lake-index-type="0"><span class="ne-text">应用场景</span></li></ol><p id="u62bd9f03" class="ne-p"><span class="ne-text">需要 全局唯一对象 的场景，例如配置管理器、日志管理器、缓存管理器。</span></p><p id="udde03c92" class="ne-p"><span class="ne-text">频繁创建对象开销大 的场景，如数据库连接池、线程池。</span></p><p id="uba60e87d" class="ne-p"><span class="ne-text">控制资源访问或协调系统中某些全局操作的场景。</span></p><ol start="3" class="ne-ol"><li id="u87588d82" data-lake-index-type="0"><span class="ne-text">优缺点</span></li></ol><p id="u7edd3f02" class="ne-p"><span class="ne-text">优点：</span></p><p id="uca2aca9e" class="ne-p"><span class="ne-text">保证全局唯一，避免重复创建资源消耗。</span></p><p id="u0663ebe7" class="ne-p"><span class="ne-text">提供统一访问点，方便管理和维护。</span></p><p id="ud694867a" class="ne-p"><span class="ne-text">缺点：</span></p><p id="u401307a2" class="ne-p"><span class="ne-text">单例对象生命周期长，可能造成内存占用。</span></p><p id="ua8eb2bb4" class="ne-p"><span class="ne-text">并发访问需要考虑线程安全，增加实现复杂度。</span></p><p id="u3f925dea" class="ne-p"><span class="ne-text">在某些场景下不易扩展，过度使用会导致系统耦合度高。</span></p></details>
<details class="lake-collapse"><summary id="u69a4784e"><span class="ne-text">有哪些使用实例</span></summary><ul class="ne-ul"><li id="u497b62bd" data-lake-index-type="0"><span class="ne-text">一个是Spring Framework 中的单例Bean</span></li><li id="u54cede48" data-lake-index-type="0"><span class="ne-text">然后是 Java.lang.Runtime 类，Runtime封装了Java应用运行时的环境。每个Java应用只有一个运行时环境，所以必须用单例来保证唯一性。</span></li><li id="u86a5fbcc" data-lake-index-type="0"><span class="ne-text">还有日志框架中，日志记录器（Logger）通常也是以单例或类似单例的模式（如缓存池）来管理的。是为了避免为每个需要日志的类都创建一个新的Logger对象，造成资源浪费，并保证日志输出的统一管理。</span></li></ul></details>
<details class="lake-collapse"><summary id="u463515d3"><span class="ne-text">常见的单例模式实现？优缺点？如何保证线程安全？</span></summary><h3 id="e62531a8"><span class="ne-text">单例模式的几种写法（从基础到完美）</span></h3><p id="uf1a7ad90" class="ne-p"><span class="ne-text">单例模式的实现关键在于：</span><span class="ne-text">1）构造方法私有化；2）自行创建实例；3）提供获取实例的静态方法。</span><span class="ne-text"> 难点在于如何处理多线程环境。</span></p><h4 id="3f333db1"><span class="ne-text">1. 饿汉式</span></h4><pre data-language="java" id="WLIRm" class="ne-codeblock language-java"><code>public class EagerSingleton {
    // 1. 静态常量，在类加载时就完成实例化
    private static final EagerSingleton INSTANCE = new EagerSingleton();

    // 2. 私有构造方法，堵死外部通过new创建实例的可能
    private EagerSingleton() {}

    // 3. 提供全局访问点
    public static EagerSingleton getInstance() {
        return INSTANCE;
    }
}</code></pre><ul class="ne-ul"><li id="u51f64352" data-lake-index-type="0"><span class="ne-text">优点</span><span class="ne-text">：实现简单，无线程安全问题。</span></li><li id="ua504f768" data-lake-index-type="0"><span class="ne-text">缺点</span><span class="ne-text">：</span><span class="ne-text">不管用不用，类加载时就创建实例</span><span class="ne-text">，如果实例很耗资源，或者始终没被用到，会造成内存浪费。不符合“懒加载”思想。</span></li></ul><h4 id="f26fb65e"><span class="ne-text">2. 懒汉式（Lazy Initialization）- 线程不安全版</span></h4><pre data-language="java" id="i7rym" class="ne-codeblock language-java"><code>public class UnsafeLazySingleton {
    private static UnsafeLazySingleton instance;

    private UnsafeLazySingleton() {}

    public static UnsafeLazySingleton getInstance() {
        // 如果instance为null，则创建
        if (instance == null) {
            instance = new UnsafeLazySingleton(); // ！！！多线程下会创建多个实例
        }
        return instance;
    }
}</code></pre><ul class="ne-ul"><li id="uc4102ec3" data-lake-index-type="0"><span class="ne-text">缺点</span><span class="ne-text">：</span><span class="ne-text">线程不安全</span><span class="ne-text">。如果两个线程同时进入</span><span class="ne-text"> </span><code class="ne-code"><span class="ne-text">if (instance == null)</span></code><span class="ne-text">判断，就会创建两个实例。</span></li></ul><h4 id="35e29302"><span class="ne-text">3. 懒汉式 - 线程安全版（同步方法）</span></h4><pre data-language="java" id="JghFj" class="ne-codeblock language-java"><code>public class SynchronizedLazySingleton {
    private static SynchronizedLazySingleton instance;

    private SynchronizedLazySingleton() {}

    // 使用synchronized关键字修饰方法，保证线程安全
    public static synchronized SynchronizedLazySingleton getInstance() {
        if (instance == null) {
            instance = new SynchronizedLazySingleton();
        }
        return instance;
    }
}</code></pre><ul class="ne-ul"><li id="u159cab96" data-lake-index-type="0"><span class="ne-text">优点</span><span class="ne-text">：线程安全。</span></li><li id="u20769859" data-lake-index-type="0"><span class="ne-text">缺点</span><span class="ne-text">：</span><span class="ne-text">效率太低</span><span class="ne-text">。</span><code class="ne-code"><span class="ne-text">synchronized</span></code><span class="ne-text">修饰整个方法，每次调用</span><code class="ne-code"><span class="ne-text">getInstance()</span></code><span class="ne-text">都要同步，而实际上只需要在第一次创建实例时同步。</span></li></ul><h4 id="41d8a399"><span class="ne-text">4. 双重检查锁（Double-Checked Locking - DCL）</span></h4><pre data-language="java" id="mfGTj" class="ne-codeblock language-java"><code>public class DCLSingleton {
    // 使用volatile关键字禁止指令重排序，这是关键！
    private static volatile DCLSingleton instance;

    private DCLSingleton() {}

    public static DCLSingleton getInstance() {
        // 第一次检查：如果instance不为null，直接返回，避免不必要的同步
        if (instance == null) {
            // 同步代码块
            synchronized (DCLSingleton.class) {
                // 第二次检查：进入同步块后再次检查，确保只有一个线程创建实例
                if (instance == null) {
                    instance = new DCLSingleton(); // 1. 分配内存 2. 初始化对象 3. 将instance指向内存地址
                }
            }
        }
        return instance;
    }
}</code></pre><ul class="ne-ul"><li id="u27e8ed8f" data-lake-index-type="0"><span class="ne-text">为什么用</span><code class="ne-code"><span class="ne-text">volatile</span></code><span class="ne-text">？</span></li></ul><ul class="ne-list-wrap"><ul ne-level="1" class="ne-ul"><li id="uf009eac7" data-lake-index-type="0"><code class="ne-code"><span class="ne-text">instance = new DCLSingleton();</span></code><span class="ne-text">这行代码并非原子操作，它可能被JVM指令重排序为 1-&gt;3-&gt;2。</span></li><li id="u5d3aa85a" data-lake-index-type="0"><span class="ne-text">如果线程A执行了1和3，但还没执行2，此时instance已不为null。线程B在第一次检查时发现instance不为null，便直接返回一个</span><span class="ne-text">尚未初始化完成</span><span class="ne-text">的对象，导致错误。</span></li><li id="u7e21481f" data-lake-index-type="0"><code class="ne-code"><span class="ne-text">volatile</span></code><span class="ne-text">关键字可以防止这种指令重排序，保证写操作之前的代码不会重排序到写操作之后。</span></li></ul></ul><ul class="ne-ul"><li id="uc4a19e5d" data-lake-index-type="0"><span class="ne-text">优点</span><span class="ne-text">：线程安全，延迟加载，效率较高。</span></li><li id="u668818fa" data-lake-index-type="0"><span class="ne-text">缺点</span><span class="ne-text">：实现稍复杂，但已是经典写法。</span></li></ul><h4 id="852f5731"><span class="ne-text">5. 静态内部类（Static Inner Class） - 推荐使用</span></h4><pre data-language="java" id="ZoUFr" class="ne-codeblock language-java"><code>public class InnerClassSingleton {
    // 1. 私有构造
    private InnerClassSingleton() {}

    // 2. 静态内部类
    private static class SingletonHolder {
        private static final InnerClassSingleton INSTANCE = new InnerClassSingleton();
    }

    // 3. 获取实例
    public static InnerClassSingleton getInstance() {
        return SingletonHolder.INSTANCE;
    }
}</code></pre><ul class="ne-ul"><li id="u3e63a0f9" data-lake-index-type="0"><span class="ne-text">原理</span><span class="ne-text">：</span></li></ul><ul class="ne-list-wrap"><ul ne-level="1" class="ne-ul"><li id="udcf7a6f7" data-lake-index-type="0"><span class="ne-text">JVM在加载外部类时，不会加载其内部类。</span><code class="ne-code"><span class="ne-text">SingletonHolder</span></code><span class="ne-text">是一个静态内部类，不依赖于外部类的实例。</span></li><li id="ue6822e13" data-lake-index-type="0"><span class="ne-text">只有当调用</span><code class="ne-code"><span class="ne-text">getInstance()</span></code><span class="ne-text">方法时，才会触发JVM加载</span><code class="ne-code"><span class="ne-text">SingletonHolder</span></code><span class="ne-text">类，从而初始化</span><code class="ne-code"><span class="ne-text">INSTANCE</span></code><span class="ne-text">。</span></li><li id="u0eac94a7" data-lake-index-type="0"><span class="ne-text">类的初始化阶段是线程安全的</span><span class="ne-text">，JVM会保证一个类的</span><code class="ne-code"><span class="ne-text">&lt;clinit&gt;()</span></code><span class="ne-text">方法（类构造器）被正确加锁同步。</span></li></ul></ul><ul class="ne-ul"><li id="ua60edadf" data-lake-index-type="0"><span class="ne-text">优点</span><span class="ne-text">：实现了</span><span class="ne-text">懒加载</span><span class="ne-text">，由JVM保证</span><span class="ne-text">线程安全</span><span class="ne-text">，实现简单。这是一种优雅的实现方式。</span></li></ul><h4 id="4530dd7a"><span class="ne-text">6. 枚举（Enum） - 《Effective Java》作者强力推荐</span></h4><pre data-language="java" id="XnPvZ" class="ne-codeblock language-java"><code>public enum EnumSingleton {
    INSTANCE; // 这就是单例的实例

    // 可以添加业务方法
    public void doSomething() {
        System.out.println(&quot;Doing something...&quot;);
    }
}

// 使用方式：
// EnumSingleton.INSTANCE.doSomething();</code></pre><ul class="ne-ul"><li id="u5c2d45ca" data-lake-index-type="0"><span class="ne-text">优点</span><span class="ne-text">：</span></li></ul><ol class="ne-list-wrap"><ol ne-level="1" class="ne-ol"><li id="ub136f5dc" data-lake-index-type="0"><span class="ne-text">绝对防止多次实例化</span><span class="ne-text">：即使面对复杂的序列化或反射攻击，枚举也能保证只有一个实例。JVM从底层确保枚举值的唯一性。</span></li><li id="ufa63bb69" data-lake-index-type="0"><span class="ne-text">线程安全</span><span class="ne-text">：枚举的初始化本身就是线程安全的。</span></li><li id="u850e6e7c" data-lake-index-type="0"><span class="ne-text">实现简单</span><span class="ne-text">。</span></li></ol></ol><ul class="ne-ul"><li id="uabc9f9fd" data-lake-index-type="0"><span class="ne-text">缺点：不够灵活（无法继承其他类，是</span><code class="ne-code"><span class="ne-text">final</span></code><span class="ne-text">的），但大多数场景下这不算缺点。</span></li></ul></details>
<details class="lake-collapse"><summary id="udd6a8de2"><span class="ne-text">为什么枚举实现是最佳实践？</span></summary><p id="u8feeacb6" class="ne-p"><strong><span class="ne-text">枚举实现</span></strong><span class="ne-text">是最佳实践，因为它 </span><strong><span class="ne-text">天然线程安全、单例唯一、可防止反射和序列化漏洞</span></strong><span class="ne-text">，同时代码最简洁。  </span></p></details>
### 工厂模式
(简单工厂/工厂方法/抽象工厂)

<details class="lake-collapse"><summary id="uec0f2124"><span class="ne-text">是什么？应用场景？优缺点？</span></summary><p id="udd17b004" class="ne-p"><strong><span class="ne-text">1. 是什么</span></strong><span class="ne-text"><br /></span><span class="ne-text">工厂模式是一种 </span><strong><span class="ne-text">创建型设计模式</span></strong><span class="ne-text">，它将对象的创建逻辑 </span><strong><span class="ne-text">封装在工厂类中</span></strong><span class="ne-text">，客户端通过工厂而不是直接 new 来获取对象，从而 </span><strong><span class="ne-text">解耦对象的创建和使用</span></strong><span class="ne-text">。</span></p><hr id="K4cIC" class="ne-hr"><p id="ude235d6c" class="ne-p"><strong><span class="ne-text">2. 核心分类</span></strong></p><ol class="ne-ol"><li id="u263411d3" data-lake-index-type="0"><strong><span class="ne-text">简单工厂模式（Simple Factory）</span></strong></li></ol><ul class="ne-list-wrap"><ul ne-level="1" class="ne-ul"><li id="u83906f28" data-lake-index-type="0"><span class="ne-text">通过一个工厂类，根据参数返回不同的产品实例。</span></li><li id="u0f75f3cb" data-lake-index-type="0"><strong><span class="ne-text">优点</span></strong><span class="ne-text">：客户端无需关心对象具体创建逻辑。</span></li><li id="ub4f9680c" data-lake-index-type="0"><strong><span class="ne-text">缺点</span></strong><span class="ne-text">：工厂类职责单一但集中过重，违反开闭原则（每增加新产品都需修改工厂）。</span></li></ul></ul><pre data-language="java" id="kNeq7" class="ne-codeblock language-java"><code>public class CarFactory {
    public static Car createCar(String type) {
        if (&quot;Benz&quot;.equals(type)) return new Benz();
        else if (&quot;BMW&quot;.equals(type)) return new BMW();
        return null;
    }
}</code></pre><ol start="2" class="ne-ol"><li id="u87951f5f" data-lake-index-type="0"><strong><span class="ne-text">工厂方法模式（Factory Method）</span></strong></li></ol><ul class="ne-list-wrap"><ul ne-level="1" class="ne-ul"><li id="u3c853fa3" data-lake-index-type="0"><span class="ne-text">为每个产品定义一个具体工厂类，工厂负责创建对应产品。</span></li><li id="u25c7543f" data-lake-index-type="0"><strong><span class="ne-text">优点</span></strong><span class="ne-text">：符合开闭原则，增加新产品无需修改原有工厂。</span></li><li id="u1ec6721f" data-lake-index-type="0"><strong><span class="ne-text">缺点</span></strong><span class="ne-text">：工厂类数量多，系统复杂度增加。</span></li></ul></ul><pre data-language="java" id="BMpGS" class="ne-codeblock language-java"><code>public interface CarFactory {
    Car createCar();
}
public class BenzFactory implements CarFactory {
    public Car createCar() { return new Benz(); }
}</code></pre><ol start="3" class="ne-ol"><li id="u5782f082" data-lake-index-type="0"><strong><span class="ne-text">抽象工厂模式（Abstract Factory）</span></strong></li></ol><ul class="ne-list-wrap"><ul ne-level="1" class="ne-ul"><li id="u81e8188b" data-lake-index-type="0"><span class="ne-text">提供接口创建一组相关或依赖的产品族，而无需指定具体类。</span></li><li id="u67be7735" data-lake-index-type="0"><strong><span class="ne-text">优点</span></strong><span class="ne-text">：一次创建一整套产品，保证产品之间的兼容性。</span></li><li id="u407788d4" data-lake-index-type="0"><strong><span class="ne-text">缺点</span></strong><span class="ne-text">：增加产品族时需要修改接口或增加工厂实现。</span></li></ul></ul><pre data-language="java" id="XgpqS" class="ne-codeblock language-java"><code>public interface GUIFactory {
    Button createButton();
    TextField createTextField();
}
public class MacFactory implements GUIFactory { ... }
public class WindowsFactory implements GUIFactory { ... }</code></pre><hr id="NlT71" class="ne-hr"><p id="udebb2ce6" class="ne-p"><strong><span class="ne-text">3. 应用场景</span></strong></p><ul class="ne-ul"><li id="u0cf67ca4" data-lake-index-type="0"><span class="ne-text">对象的创建逻辑复杂，或者客户端无需关心具体类。</span></li><li id="uc9380ba0" data-lake-index-type="0"><span class="ne-text">系统需要灵活扩展产品种类时。</span></li><li id="u2e1a745b" data-lake-index-type="0"><span class="ne-text">保证同一产品族中对象的一致性或兼容性。</span></li></ul></details>
<details class="lake-collapse"><summary id="u6e53fbd7"><span class="ne-text">有哪些使用实例</span></summary><ul class="ne-ul"><li id="ufff2afb6" data-lake-index-type="0"><span class="ne-text">一个是 Spring Framework 的 </span><code class="ne-code"><span class="ne-text">BeanFactory</span></code><span class="ne-text">，BeanFactory 是最基本的工厂接口，ApplicationContext 是 BeanFactory 的高级实现，实际项目中我们使用的就是它。</span></li><li id="ufb6885b5" data-lake-index-type="0"><span class="ne-text">然后是JDK - </span><code class="ne-code"><span class="ne-text">Collection.iterator()</span></code><span class="ne-text">是工厂方法，</span><code class="ne-code"><span class="ne-text">Collection</span></code><span class="ne-text">接口定义了 </span><code class="ne-code"><span class="ne-text">iterator()</span></code><span class="ne-text">这个工厂方法。</span><code class="ne-code"><span class="ne-text">ArrayList</span></code><span class="ne-text">和 </span><code class="ne-code"><span class="ne-text">HashSet</span></code><span class="ne-text">作为具体工厂，分别重写 </span><code class="ne-code"><span class="ne-text">iterator()</span></code><span class="ne-text">方法，返回它们各自专用的迭代器 </span><code class="ne-code"><span class="ne-text">Itr</span></code><span class="ne-text">和 </span><code class="ne-code"><span class="ne-text">KeyIterator</span></code><span class="ne-text">作为具体产品。</span></li><li id="uc0185f65" data-lake-index-type="0"><span class="ne-text">应用实践中的一个典型例子就是支付系统</span></li><li id="u2714e664" data-lake-index-type="0"><span class="ne-text">当你看到代码中出现大量的 </span><code class="ne-code"><span class="ne-text">if-else</span></code><span class="ne-text">或 </span><code class="ne-code"><span class="ne-text">switch-case</span></code><span class="ne-text">来创建不同类型的对象时，就应该立刻想到——这里可以用工厂模式来优化</span></li></ul></details>
### 建造者模式
<details class="lake-collapse"><summary id="u82e4f373"><span class="ne-text">是什么？应用场景？优缺点？</span></summary><p id="u4274a96c" class="ne-p"><span class="ne-text">建造者模式是为了解决复杂对象的创建问题。建造者模式通过一个内部静态类（Builder），使用链式方法调用的方式，一步步设置复杂对象的参数，最后通过</span><code class="ne-code"><span class="ne-text">build()</span></code><span class="ne-text">方法生成一个稳定、完整的产品对象。它完美解决了多参数对象创建时的可读性、安全性和灵活性问题。</span></p><hr id="zt3rt" class="ne-hr"><p id="ubcd661e5" class="ne-p"><span class="ne-text">应用场景：</span></p><ul class="ne-ul"><li id="u30a598c7" data-lake-index-type="0"><span class="ne-text">当创建一个对象需要很多步骤，并且这些步骤的顺序可以是灵活的。</span></li><li id="uffa87d29" data-lake-index-type="0"><span class="ne-text">当同一个创建过程需要产生不同的产品对象时。</span></li><li id="u788758ab" data-lake-index-type="0"><span class="ne-text">当要创建的产品对象有复杂的内部结构，并且内部属性本身也可能是复杂的对象。</span></li><li id="ue2f393c4" data-lake-index-type="0"><span class="ne-text">最主要、最常见的场景：当一个类的构造方法参数过多（比如超过4个），且很多参数都是可选时，使用建造者模式可以极大地提升代码的可读性和可维护性。</span></li></ul><hr id="zkZoY" class="ne-hr"><h4 id="tYEkr"><span class="ne-text">优点</span></h4><ul class="ne-ul"><li id="uab63ac32" data-lake-index-type="0"><span class="ne-text">创建逻辑清晰，步骤稳定</span></li><li id="u09584ef4" data-lake-index-type="0"><span class="ne-text">可构造不同配置信息的对象，灵活扩展</span></li><li id="u134837c7" data-lake-index-type="0"><span class="ne-text">参数可读性强，不会出现构造器爆炸</span></li><li id="u14965359" data-lake-index-type="0"><span class="ne-text">便于维护，链式调用友好</span></li></ul><h4 id="Te0DD"><span class="ne-text">缺点</span></h4><ul class="ne-ul"><li id="u3f929e0b" data-lake-index-type="0"><span class="ne-text">类数量增多，多一个 Builder 类</span></li><li id="ufb89a49f" data-lake-index-type="0"><span class="ne-text">构建步骤复杂时可能需要大量代码</span></li></ul></details>

### 代理模式
<details class="lake-collapse"><summary id="udcfc6374"><span class="ne-text">代理模式（静态代理+动态代理）</span></summary><p id="u47423708" class="ne-p"><span class="ne-text" style="color: rgb(51, 51, 51)">代理模式简单来说就是 </span><strong><span class="ne-text" style="color: rgb(51, 51, 51)">我们使用代理对象来代替对真实对象(real object)的访问，这样就可以在不修改原目标对象的前提下，提供额外的功能操作，扩展目标对象的功能。</span></strong></p><p id="udf13f1ce" class="ne-p"><strong><span class="ne-text" style="color: rgb(51, 51, 51)">代理模式的主要作用是扩展目标对象的功能，比如说在目标对象的某个方法执行前后你可以增加一些自定义的操作。</span></strong></p><p id="ue9301c12" class="ne-p"><span class="ne-text" style="color: rgb(51, 51, 51)">代理模式有静态代理和动态代理两种实现方式：</span></p></details>
<details class="lake-collapse"><summary id="u0b9651a2"><span class="ne-text">静态代理</span></summary><p id="u33886f10" class="ne-p"><span class="ne-text" style="color: rgb(51, 51, 51)">静态代理中，我们对目标对象的每个方法的增强都是手动完成的，</span><strong><span class="ne-text" style="color: rgb(51, 51, 51)">非常不灵活（比如接口一旦新增加方法，目标对象和代理对象都要进行修改）且麻烦(需要对每个目标类都单独写一个代理类）</span></strong></p><p id="ue4fdf3ac" class="ne-p"><span class="ne-text" style="color: rgb(51, 51, 51)">从 JVM 层面来说， </span><strong><span class="ne-text" style="color: rgb(51, 51, 51)">静态代理在编译时就将接口、实现类、代理类这些都变成了一个个实际的 class 文件。</span></strong></p><p id="uaee5150f" class="ne-p"><strong><span class="ne-text" style="color: rgb(51, 51, 51)">实现步骤</span></strong><span class="ne-text" style="color: rgb(51, 51, 51)">：</span></p><p id="u7a409220" class="ne-p"><span class="ne-text" style="color: rgb(51, 51, 51)">1，定义一个接口及其实现类</span></p><p id="u20116b4f" class="ne-p"><span class="ne-text" style="color: rgb(51, 51, 51)">2，创建一个代理类同样实现这个接口</span></p><p id="u28756193" class="ne-p"><span class="ne-text" style="color: rgb(51, 51, 51)">3，将目标对象注入进代理类，然后在代理类的对应方法调用目标类中的对应方法。这样的话，我们就可以通过代理类屏蔽对目标对象的访问，并且可以在目标方法执行前后做一些自己想做的事情</span></p><div class="ne-quote"><p id="ud1e93420" class="ne-p"><span class="ne-text" style="color: rgb(119, 119, 119)">静态代理就是写一个代理类，这个类实现和目标类一样的接口，然后在方法里，</span><strong><span class="ne-text" style="color: rgb(119, 119, 119)">手动在调用目标方法的前后加上你想要的逻辑</span></strong><span class="ne-text" style="color: rgb(119, 119, 119)">，比如日志、权限校验、时间统计等等。</span></p></div></details>
<details class="lake-collapse"><summary id="ua7c35e1c"><span class="ne-text" style="color: rgb(51, 51, 51)">动态代理</span></summary><p id="uab706479" class="ne-p"><span class="ne-text" style="color: rgb(51, 51, 51)">相比于静态代理来说，动态代理更加灵活。我们不需要针对每个目标类都单独创建一个代理类，并且也不需要我们必须实现接口。Spring AOP、RPC 框架的实现都依赖了动态代理。</span></p><p id="u32bc84dd" class="ne-p"><strong><span class="ne-text" style="color: rgb(51, 51, 51)">从 JVM 角度来说，动态代理是在运行时动态生成类字节码，并加载到 JVM 中的</span></strong></p><h3 id="9c004bdc"><span class="ne-text" style="color: rgb(51, 51, 51)">JDK的动态代理</span></h3><p id="u8ce32878" class="ne-p"><code class="ne-code"><strong><span class="ne-text" style="color: rgb(51, 51, 51); background-color: rgb(243, 244, 244)">InvocationHandler</span></strong></code><strong><span class="ne-text" style="color: rgb(51, 51, 51)"> 接口和 </span></strong><code class="ne-code"><strong><span class="ne-text" style="color: rgb(51, 51, 51); background-color: rgb(243, 244, 244)">Proxy</span></strong></code><strong><span class="ne-text" style="color: rgb(51, 51, 51)"> 类是核心。</span></strong></p><p id="u81f99cf1" class="ne-p"><code class="ne-code"><span class="ne-text" style="color: rgb(51, 51, 51); background-color: rgb(243, 244, 244)">InvocationHandler</span></code><span class="ne-text" style="color: rgb(51, 51, 51)"> 接口的对象。</span></p><p id="ud3236320" class="ne-p"><span class="ne-text" style="color: rgb(51, 51, 51)">要实现动态代理的话，还必须需要实现</span><code class="ne-code"><span class="ne-text" style="color: rgb(51, 51, 51); background-color: rgb(243, 244, 244)">Enhancer</span></code><span class="ne-text" style="color: rgb(51, 51, 51)"> 类的 </span><code class="ne-code"><span class="ne-text" style="color: rgb(51, 51, 51); background-color: rgb(243, 244, 244)">create()</span></code><span class="ne-text" style="color: rgb(51, 51, 51)">创建代理类；</span></li></ol><h2 id="f5deaa17"><span class="ne-text" style="color: rgb(51, 51, 51)">对比</span></h2><p id="u89925e82" class="ne-p"><strong><span class="ne-text" style="color: rgb(51, 51, 51)">灵活性</span></strong><span class="ne-text" style="color: rgb(51, 51, 51)">：动态代理更加灵活，不需要必须实现接口，可以直接代理实现类，并且可以不需要针对每个目标类都创建一个代理类。另外，静态代理中，接口一旦新增加方法，目标对象和代理对象都要进行修改，这是非常麻烦的！</span></p><p id="uaa476b81" class="ne-p"><strong><span class="ne-text" style="color: rgb(51, 51, 51)">JVM 层面</span></strong><span class="ne-text" style="color: rgb(51, 51, 51)">：静态代理在编译时就将接口、实现类、代理类这些都变成了一个个实际的 class 文件。而动态代理是在运行时动态生成类字节码，并加载到 JVM 中的。</span></p></details>
<details class="lake-collapse"><summary id="ubb7e33e3"><span class="ne-text">代理模式和适配器模式有什么区别？</span></summary><p id="u3c330467" class="ne-p"><strong><span class="ne-text" style="color: rgb(51, 51, 51)">目的不同</span></strong><span class="ne-text" style="color: rgb(51, 51, 51)">：代理模式主要关注控制对对象的访问，而适配器模式则用于接口转换，使不兼容的类能够一起工作。</span></p><p id="u1f0e5195" class="ne-p"><strong><span class="ne-text" style="color: rgb(51, 51, 51)">结构不同</span></strong><span class="ne-text" style="color: rgb(51, 51, 51)">：代理模式一般包含抽象主题、真实主题和代理三个角色，适配器模式包含目标接口、适配器和被适配者三个角色。</span></p><p id="ud334a168" class="ne-p"><strong><span class="ne-text" style="color: rgb(51, 51, 51)">应用场景不同</span></strong><span class="ne-text" style="color: rgb(51, 51, 51)">：代理模式常用于添加额外功能或控制对对象的访问，适配器模式常用于让不兼容的接口协同工作。</span></p></details>
